## 2. 试测如何进行

首轮建议 4 位能阅读中文、此前未用过该原型的人，手机和桌面各 2 位。由项目负责人决定是否组织。本轮采用虚构情境，不需要参与者提供个人借款或占问经历。先由维护者排演一次，单列内部记录；真人环节另开记录表。此方案只考察问卦者本人的四种资金角色、经营与资本收益，以及范围外退出。

每人完成下表各题。奇数编号从第 1 题开始，偶数编号倒序进行；每题从新会话开始。仅向参与者展示“任务卡”，隐藏预期和开发者模拟面板中的细节（主持时不引导使用该面板）。主持人统一说明“请按卡片里的情况操作，到你认为这次已经处理完为止”。首次完成前不解释选择含义。求助时先记录首次状态，再另记提示后的结果。每题结束后请对方用自己的话说出页面记住了哪些事，以及这次先看哪件。

| 编号 | 任务卡（参与者可见） | 预期（主持人用） |
| --- | --- | --- |
| 1 | 修屋顶还差三万元。你打算找姐姐周转，想知道她会不会答应。 | 新借入；自己收款 |
| 2 | 朋友的店临时缺钱，希望你先垫两万元，下月归还。你想知道该不该答应。 | 新出借；自己提供资金 |
| 3 | 去年你垫给同事的钱到期了。你想问这个月能不能拿回来。 | 收债；自己是债权人 |
| 4 | 你去年从同事那里周转的钱到期了。你想知道这个月能不能结清。 | 还债；自己是债务人 |
| 5 | 你有两件事想问。一是自己的面馆下季生意如何，二是你买的一只基金年底能赚多少。这次最挂心基金，面馆的事也希望留在清单上。 | 两项齐全；主目标为资本收益 |
| 6 | 两个人分别欠你设备款和材料款。两笔都想问，这次先看材料款。 | 两个独立收债实例；能辨认并选中材料款。仅有一个路线名不足以得分 |
| 7 | 你负责整理一笔家里的往来款，只知道与你有关，暂时弄不清究竟是谁欠谁。请按现有信息处理。 | 不确定并停止；没有确认资金方向 |
| 8 | 你姐姐借出去的钱一直没收回来。她请你替她问进展，钱与你无关。 | 第三方，按其他事情退出 |
| 9 | 先确认自己要收回一笔旧款。完成后主持人再给第二张卡：“刚核对了凭据，是你欠对方。请改正原问题并处理。” | 观察修改原问句后旧清单与主目标是否失效、参与者能否重新确认为还债 |

这些是界面操作卡，只用于本轮观察。不得送入编码、训练或阈值搜索，也不计入独立模型验证。

## 3. 记录、分母与判读

每人每题一行，记录匿名编号、设备、题号、首次所列目标与角色、所选主目标、最终屏幕状态、参与者复述、是否求助、修改次数、重复确认次数、用时和备注。计时从看到卡片到首次自行结束；主动退出也记结束时间。可记录多个错误标签。首次结果锁定后再记录纠正情况。第 9 题把预设的第二阶段与主动返工分开计数。

| 指标 | 计数办法 |
| --- | --- |
| 无协助完成 | 首次结束时清单、角色、主目标或预期退出均符合题卡，且无提示。逐题报告人数/尝试人数 |
| 资金方向误确认 | 第 1–4 题及第 9 题更正阶段，按各自的尝试人数报告错误完成数。另记曾误选后自行修正数 |
| 漏项 / 主目标错误 | 第 5、6 题分别报告漏列人数/尝试人数；在完整清单中另报选错主目标人数/清单完整人数。保留每个同类实例 |
| 不确定 / 退出 | 第 7、8 题分开统计安全停止和错误确认；第 1–6 题单列清楚任务中的主动退出或放弃 |
| 重做与负担 | 分题报告耗时中位数和范围、求助人数、额外重复确认次数；记录具体卡住的步骤及参与者原话（经同意） |

优先检查“页面已完成，但人的角色或清单错了”。任一资金方向错而完成、漏项后完成、第三方被当作本人确认、或改题后仍能使用旧确认，即暂停集成讨论。先保存首次过程，定位到文字理解、实例辨识、操作顺序或状态失效，再决定修哪一处。仅有耗时偏长时，结合卡点与重复操作判读。4 人无严重错误只支持扩大试测；不据此估计总体准确率或签发上线许可。

## 4. 进入正式链路前逐项验收

- **事实来源。** 生产入口须能证明用户在当前问句与会话中明确确认每项目标、必要角色、清单完整性及多目标中的主目标。手工标注只作研究输入；抽取标签、文本位置、默认选项和页面显示都不能代替用户动作。
- **实例与失效。** 两个同类目标保留独立 ID。改原问题后清空旧事实；清单变化后重新确认完整性与主目标。旧请求、冲突来源、不确定和第三方退出均应在两条候选路径验证。
- **权限。** 对 Arbitration 与 Fallback 验证相同的角色和目标约束。保留 Semantic Act、Sufficiency 和 unsupportedTargets 的阻止作用，以及仅适用于 Fallback 的 Routeability 条件。已确认事实与独立候选冲突时拒绝选择，禁止用确认结果替换候选。
- **Fallback。** 正式使用须有当前版本可用且已锁的统一阈值、22 个有限分数和唯一接纳。现有失败候选未满足该项。演示阈值与合成分数仅用于接口检查。
- **回归与放行。** 在拟接入版本重新运行定向 Node、Chromium、上游拒绝与失效回归以及仓库 predeploy。另行按冻结的数据治理与候选验证流程评估已知 exact ≥80%、已接纳准确率 ≥98%、非路线/子类/角色误激活 ≤5%。组件回归、真人操作观察和独立模型评估分别报告。维持现有权重、阈值、current-22 与传统六爻 TR/MR 规则的冻结边界。

## 5. 独立原型是否需要立即修改

目前建议先观察原版。首页标题“这次，你最想问哪件事？”先引导用户挑一件，而下一步需要列全。正文已有“先列出，再选一件”的提示。两处文案和既有自动测试足以定位可检验的假设，还没有真人证据说明实际漏项由标题造成。第 5、6 题若出现提前收窄，追问参与者当时如何理解标题和“清单完整”，再审阅仅调整该页标题或步骤提示的方案。若实际遗漏来自两笔款项显示相同，则优先检查实例标签。变更后用新的等价情境复核，保留初版结果。
