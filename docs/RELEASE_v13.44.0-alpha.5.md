# 龟甲 v13.44.0-alpha.5 · 时间效力模型重构第 5 步

本阶段新增 Candidate Output 候选用户输出层，把新的 Node Assessment 与 Evidence Selector 组合成完整候选文案，并并行生成候选日期判断 / 日期比较；正式页面仍继续使用旧输出。

## 核心变化

- 新增 `js/liuyao-time-output.js`。
- 候选节点摘要直接读取六维 Node Assessment，不读取 legacy `direction / effect`。
- 候选事实直接读取 Evidence Selector，摘要中的每个效力维度均有可见证据。
- 候选日期判断把触发、生扶、比和、受制、泄力、耗力分开；触发本身不再被当作正向加分。
- 新旧输出并行：`questionTimeFocus` 正式字段保持旧行为，同时在 `candidateOutput` 中保留候选摘要、证据和日期比较供压力测试。

## 本阶段验证重点

- 候选文案长度与证据条数是否可控。
- 新摘要是否存在无证据维度或信息丢失。
- 复合证据是否重新出现重复子事实。
- 日期比较与旧排序的差异率、差异原因与极端反例。
- 用户可见旧输出必须保持不变。

## 本阶段不做

- 不切换详细页或复制上下文到 Candidate Output。
- 不删除 legacy 摘要 / 排序逻辑。
- 不改过程型关键节点筛选。
- 不处理 1100 天长范围上限。

## 压力测试结果

### 候选节点输出

4096 个真实六爻组合 × 12 个连续日支，共 49,152 次：

- Candidate Output 无效：0。
- 运行异常：0。
- 摘要维度缺可见证据：0。
- 重复候选事实：0。
- 摘要长度平均约 7.57 字，95 分位 11 字，最大 17 字。
- 摘要证据平均约 1.74 条，95 分位 2 条，最大 4 条；超过三条仅 10 个节点。

### 过程型范围

4096 卦“8月15日至20日出差如何”：

- Candidate key date 与 legacy key date 集合不一致：0。
- 最终关键节点：11,162。
- Candidate 重复事实：0。
- 新旧摘要不同约 97.59%，用于确认新六维模型确实没有继续复制旧单轴语义；本阶段不据此切换前台。

### 日期比较

4096 卦“这周哪天适合出行”与 4096 卦“明天还是周五哪个好”共同执行不变量测试：

- comparison 缺失：0。
- comparison 第一候选并非 comparator 最优：0。
- tie 中出现不同实质效力组合：0。
- mixed 内“明确受制”错误压过同等生扶/比和但仅泄力或耗力的日期：0。
- caution 内“明确受制”错误压过仅泄力/耗力日期：0。
- 候选事实为空：0。

新旧日期选择仍存在较大差异，这是预期的诊断信号：旧排序建立在 `supportive / adverse / mixed` 单轴上，新排序建立在六维效力上。alpha.5 不把差异率本身当作正确性指标，而以六维不变量和具体反例检查作为验收依据。

### 兼容性

alpha.4 与 alpha.5 对连续范围、范围日期选择、离散日期比较各抽取 1,024 卦，共 3,072 组；去除仅内部使用的 Candidate/Assessment/Evidence 并行字段后，legacy 用户可见结果差异为 0。

## 日期比较原则

- 不使用 reasonCount 作为隐性总分。
- `preferred > secondary > mixed > observe > caution` 只表达候选类别，不等同吉凶评分。
- mixed / caution 内，明确“受制”优先视为比“泄力 / 耗力”更重的负担。
- direct / primary 可以稳定内部排序，但不用于破坏用户层的实质并列。
- 用户层 tie 依据效力种类组合，而不是事件条数或来源细节。
