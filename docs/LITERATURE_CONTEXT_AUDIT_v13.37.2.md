# 龟甲 v13.37.2 · 古籍匹配上下文审核

## 目标

本轮不改八字 / 六爻排盘规则，也不改变古籍浏览 UI 的层级体系。重点审核“复制分析上下文”里的古籍内容，确保后续分析能区分：

1. 程序已经确认的结构事实；
2. 仅作为进一步核对条件的古籍论述；
3. 尚未逐字核对、只能给出原典定位的条目。

## 主要调整

### 1. `match` 与 `contextMatch` 分离

站内古籍卡片继续使用原有 `match` 文案；复制分析上下文优先读取 `contextMatch`。

这样可以保留站内简洁匹配说明，同时在复制给后续分析模型时明确适用边界。例如《子平真诠》“食神格”条：程序只确认月令本气为食神，以及财、杀、印等相关十神出现；并不因此自动认定“食格成也”。

### 2. 八字条件论述型条目增加边界

重点覆盖：

- 《子平真诠》月令格局成败条；
- 三合 / 三会触发的“用神变化”条；
- 七杀与食神并见；
- 《渊海子平》官杀并见；
- 《千里命稿》官杀并见、刑冲合害轻重、强弱方法；
- 《三命通会》旺相休囚死方法边界；
- 少数已核对的日时 / 月时短断。

复制文本会明确：程序确认到哪一步，以及哪些成格、制化、强弱或吉凶条件尚未判定。

### 3. 修正《穷通宝鉴》同季跨月引用

审核发现原 `QIONGTONG_SEASON_INDEX` 中部分本地摘录实际只对应季首单月，例如：

- 七月戊土；
- 四月庚金；
- 十月辛金；
- 正月丁火。

此前这些摘录会被整个同季共用，导致酉月可能看到“七月戊土”等并非本月的原文。

现在处理规则为：

- “三春 / 三夏 / 三秋 / 三冬 / 春月”等季节总论：同季可直接引用；
- 明确写“正月 / 四月 / 七月 / 十月”等单月的摘录：仅对应月支匹配时引用；
- 同季其他月份：改为“条目定位”，不使用别月原文代替。

测试已覆盖十干 × 十二月全部 120 组入口。

### 4. 六爻条件型条目增加边界

对暗动、旬空、三合、反吟 / 伏吟、进退神等条目，复制上下文现在会把“程序识别到结构”与“古籍原文条件是否完整成立”分开。

例如暗动：程序可以确认当前实现的暗动提示条件，但复制文本会继续提醒旺相 / 休囚、受制、合绊等条件仍需复核。

月建、日辰、世应、六神等方法型条目也会说明其只是分析框架，不直接构成吉凶结论。

## 未改变

- 八字、六爻排盘算法；
- 古籍原文本身；
- 古籍浏览 UI 与 CSS；
- 原有 `level / levelKey / verified / sourceKind` 内部字段；
- 未核对条目仍只显示原典定位，不生成拟似古文。
