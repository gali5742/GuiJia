# 调整方向后的单次训练诊断

2026-10-11（UTC）。基线 `8887c04`，运行前合同/脚本提交 `f0b737f`。

**结论：优化不足确实影响原训练头。充分求解同一目标函数后，训练集区分与唯一接纳明显改善，但拒答问题仍存在。现在停止优化器实验，优先验证接纳与拒答边界，不继续增加大批校准语料或搜索超参数。**

本次是独立的训练专用诊断，不恢复已因数据污染停止的 v0.11，不创建可供生产或 Phase C 使用的模型/阈值锁。原损失一致性失败、原数据近重复失败及所有冻结文件保留。

## 一次受控比较

复用封存的同一 2028 条训练成员与缓存向量（1553 已知、475 非路线）。旧基准使用已封存的原训练器从零复现头；新头也从零开始，使用已冻结的 L-BFGS 实现。目标函数、512 维向量、class balancing、negative multipliers、L2=0.00025 与 bias 不正则化均不变。新参数以 Float64 保存，属于既有预设优化实现；本结果不能进一步分离求解方法与数值精度的各自贡献。

合同预设仅一次全 22 头拟合、最多每头 1000 次迭代、梯度无穷范数 ≤1e-7，不改变参数、不重试、不增加数据。本地实际运行 Node v22.23.3 / Linux x64，11 项定向实现检查通过；没有调用实际编码器或云 CI。全部 22 个新头在 24–62 次迭代内收敛，最大梯度无穷范数 9.853352841787127e-8。完整损失、梯度与训练指标已零拟合/零编码重放。

## 这次结果改变了什么判断

1. **不宜马上换编码器或扩充训练语料。** 现有向量与简单分类头在训练成员上的排名已能达到 98.97%；原优化过程确实留下了可避免的不足。这个结果不能证明未见问句也可区分，但降低了立即换架构的优先级。
2. **排名与唯一接纳是不同问题。** 新头仍有 323 条已知成员同时触发多个头；lend_money 的排名正确数为 64/66，而唯一正确接纳仅 37/66。不能把排名准确率当作最终路由准确率，也不能用 Top-1 抹去拒答约束。
3. **拒答仍需要验证。** 非路线唯一激活仍有 126/475。这是训练集上的独立头诊断，未执行 Act/Suff/Arbitration/Routeability，因此不能直接解释为正式 raw 路径误激活率或业务安全失败。但它清楚表明“收敛了就能直接使用”没有依据。
4. **没有证明泛化改善。** 训练数据既参与拟合也参与这些读数，没有新增校准、独立评测或盲评。结果只支持下一步有针对性的验证，不产生组件通过结论。

## 调整后的推进方式

- 本轮到此结束，不继续换优化器、扫参数、找阈值或增加大批问句。
- 下一步优先设计一小批全新且独立编写的诊断问句，检查资金借入/借出、追债/还债、经营/投资边界、含糊角色与多目标输入；用固定头判断训练中的改善是否延续。具体成员、标签、读数与停止条件须先确定再评分，不从旧失败问句改写。
- 小规模验证只是选择研究方向，不能替代全部 22 路线的正式覆盖与安全门槛。若训练优势不能延续，就停止优化器方向，调查标签边界与表征；若延续，再安排一次正式 all22 校准，而非循环补数据直到通过。
- 无需为了追求通过修改当前生产链或数字门槛。所有正式组件仍保持原冻结状态，Phase C 不启动。
