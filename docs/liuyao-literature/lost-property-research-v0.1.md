## 1. 现代问题范围

当前只研究**无生命财物的遗失 / 寻回 / 所在位置**。

第一阶段至少区分两个问题：

```text
A. lost_property_recovery
   某件已经遗失的无生命物品能否找回？

B. lost_property_location
   某件已经遗失的无生命物品现在在哪里？
```

典型现代问题：

- 手机丢了还能不能找到？
- 钥匙不见了，可能掉在哪里？
- 证件丢了还能找回来吗？
- 钱包丢了，是落在家里还是外面？
- 戒指不见了，现在可能在哪里？

当前明确排除：

- 宠物走失；
- 家畜、飞禽走失；
- 儿童走失；
- 家人、朋友、其他失踪人员；
- 物流尚未送达但没有确认遗失；
- 购买某物是否合适；
- 单纯追问谁偷了、能否抓到贼等独立“盗贼 / 捕盗”目标。

最后一项尤其需要保留边界：古典“失脱”章节常把失物、盗贼、捕盗合并讨论，但现代 Semantic Route 不应因此把“找东西”和“抓贼”自动视为同一个目标。

## 3. 古典占类对应

目前找到的直接传统占类主要是：

- 《火珠林》：占逃亡、占贼盗中直接讨论失物；
- 《黄金策》：`失脱（附盗贼、捕盗、捉贼）`；
- 《断易天机》：`占遗失第十七`；
- 《易隐》卷八：遗失占 / 盗贼占中的失物定位与寻获；
- 《卜筮正宗》：收录并注解《黄金策》失脱体系。

现代 `lost_property` 与古典“失脱 / 遗失”高度对应，但古典文本经常把：

```text
失物本身
+ 是否被盗
+ 贼是谁
+ 能否捕盗
+ 财物藏在哪里
```

放在连续章节中。

工程上必须重新拆分职责，不能把整章原样映射成一个 Route。

# 5. 研究命题：失物是否一律取妻财

> 以下编号是 Research Finding，不是正式 Rule Candidate ID。

## LP-RF-001：普通失物以妻财作为默认主观察对象

证据状态：`stable_consensus`

跨来源表现：

- 《火珠林》直接以“失物看财”概括；
- 《黄金策》失脱开篇要求详察妻财；
- 《断易天机》遗失歌与注解均以财爻作为失物主线；
- 《易隐》的“见否”和大量位置规则也以财爻为中心。

研究结论：

```text
generic lost possession
→ 妻财作为传统默认主观察入口
```

这足以支持“普通失物看财”是跨来源稳定传统。

但它**不能推出“所有失物无条件都看妻财”**。

---

## LP-RF-002：失物取用存在按物类切换，妻财不是绝对唯一目标

证据状态：`stable_consensus`（原则层）

关键证据：

### 《火珠林》

直接说明：

```text
若失文书牌号，当以父母爻取。
```

同时另列：

```text
六畜 → 子孙
普通失物 → 财
```

### 《黄金策》

篇末原文已经把：

```text
舟车 / 衣服
```

与普通妻财规则区分，又把：

```text
走兽 / 飞禽
```

与父母规则区分。

《卜筮正宗》等注释体系进一步明确解释为：

```text
舟车、衣服、文书券契 → 父母
飞禽走兽、六畜 → 子孙
```

研究结论：

```text
“失物”首先是事件类别，
但主观察六亲还可能取决于失去的对象本身属于哪一传统类象。
```

因此当前 legacy：

```text
lost-item → 固定妻财
```

**不能晋升为正式 Observation Rule。**

---

## LP-RF-003：文书 / 证件类失物取父母有直接古典依据

证据状态：`stable_consensus`

至少存在两条相互兼容的传统证据链：

1. 《火珠林》直接规定文书牌号遗失取父母；
2. 《黄金策》—《卜筮正宗》体系把文书券契列入父母类失物。

现代映射可较谨慎地覆盖：

- 证件；
- 票据；
- 合同原件；
- 纸质 / 载体型文书。

但“电子文件”“云端数据”等是否可直接沿用，属于后续现代语义映射问题，不能只凭“文书”二字自动扩张。

---

## LP-RF-004：舟车、衣服等日常用品取父母已有传统支持，但现代物品分类仍需功能判断

证据状态：`cross_source_compatible`

《黄金策》及其注释体系把舟车、衣服与父母类相连。

朱辰彬现代体系进一步把：

- 电话；
- 物件；
- 钥匙；
- 日常佩戴戒指；

归入父母取用，并提供实际寻物案例。

但现代物件存在多重功能：

```text
同一枚戒指
- 日常佩戴用品 → 父母
- 收藏 / 保值资产 → 妻财
```

因此不能把现代对象名称本身硬编码为固定六亲。

正确研究方向应是：

```text
现实对象
↓
在本次占问中的主要功能 / 使用关系
↓
传统物类
↓
主观察六亲
```

而不是：

```text
手机 = 父母
戒指 = 父母
```

永久固定。

# 6. 主观察与辅助观察的初步职责划分

## 6.1 Primary：失物本体

主观察对象首先由失物传统类象决定：

```text
普通财物 / 财产性物件 → 妻财（默认）
文书、证件类 → 父母（直接传统支持）
舟车、衣服、用品类 → 父母（传统 + 现代兼容支持）
动物 → 子孙（传统稳定，但本 Route 排除）
```

目前仍不能给出一张覆盖所有现代物品的最终映射表。

## 6.2 世爻：占者 / 寻回关系

世爻不是失物本体的替代用神。

传统证据显示：

- “静临世上”可作为物尚在、容易关联到占者的信号；
- 《易隐》把“生合世”列入可见条件之一。

因此世爻更适合作为：

```text
role observation / recovery relation
```

而非全局 Primary。

## 6.3 官鬼：盗窃 / 转移原因的条件观察

《黄金策》《火珠林》等都把官鬼与贼盗联系。

但不能写成：

```text
卦中有官鬼 = 一定被偷
```

更稳妥的是：

- 官鬼发动、出现并符合相应条件，可成为“盗窃可能”证据；
- 无鬼、鬼空 / 伏静配合其他条件，传统上可支持“自失”方向；
- 这是 `loss_context` 的辅助判断，不改变失物本体 Primary。

## 6.4 子孙：捕捉 / 知情 / 解鬼等专项角色

古典盗贼部分常以子孙克鬼论捕捉，并在《易隐》中用于“知情”等专项。

对于本项目第一阶段：

```text
lost_property_recovery / location
```

子孙不应默认成为核心观察对象。

只有未来若扩展“追贼 / 捕盗”等独立目标，才应重新专项研究。

# 7. “能否找回”规则研究

## LP-RF-010：旺相、有气、出现、安静是可寻的重要正面条件

证据状态：`stable_consensus`

跨来源共同方向：

- 财 / 用神旺相、有气；
- 不空；
- 出现；
- 安静；
- 内卦 / 本宫；

通常更倾向：

```text
物未散 / 未远 / 可寻
```

这类条件在《火珠林》《黄金策》《断易天机》《易隐》中反复出现。

---

## LP-RF-011：空、化空、衰绝、受破害等是难寻的重要负面条件

证据状态：`stable_consensus`（方向），细节仍需专项核证

古典失物占普遍把：

- 自空 / 化空；
- 空亡；
- 衰绝；
- 刑害克破；

视为不利于寻获的信号。

但正式工程规则不能简单写成：

```text
见空 = 永远找不到
```

原因：

1. 一般六爻体系对空亡还有冲实、出空、动空等时效层；
2. 当前龟甲 Time Engine 已冻结；
3. 失物专项必须先区分“当前不可见”“物已散”“等待出空可见”等不同命题。

因此这里只固定“负面证据方向”，不在本研究阶段改时间算法。

---

## LP-RF-012：动爻首先表示移动 / 更变，不宜机械等同“绝对找不到”

证据状态：`cross_source_compatible`

传统材料常说：

- 财动则物出；
- 外财旺动则远去；
- 财伏逢冲有人移物；

因此“动”很重要，但其首要含义往往是：

```text
位置发生变化 / 已移动 / 距离增加 / 更难定位
```

而不是无条件：

```text
动 = 永失
```

正式规则必须保留动爻与：

- 旺衰；
- 内外；
- 合冲；
- 墓伏；
- 世用关系；

的组合条件。

---

## LP-RF-013：世用关系可参与“是否可寻”，但不是单独裁决器

证据状态：`cross_source_compatible`

传统有：

- 用神静临世；
- 用神生合世；

作为“尚在 / 可见”的正面信号。

因此未来 ObservationPlan 很可能需要：

```text
Primary lost object
+
Self / recovery relation（世）
```

但目前还不足以确定：

```text
世弱 = 一定找不到
```

朱辰彬《进阶篇》甚至明确区分：

- 问“在哪里”时属于现状信息，重心在用神；
- 问“最终能否找到”时才涉及不同的结果判断。

这进一步说明 location 与 recovery 不应混用同一套结论。

---

## LP-RF-014：墓、伏、合可以是“藏匿 / 遮掩 / 容器”信息，不能一律当作失败

证据状态：`stable_consensus`（取象方向）

《黄金策》与后世注解明确把：

- 入墓；
- 伏藏；
- 日辰合住；

用于解释：

```text
深藏
器物内
被遮掩
被他物覆盖
```

某些情况下这些状态同时增加寻获难度，但“墓 / 伏”还承担位置与显隐信息。

因此程序不能建立：

```text
墓 = lost_forever
伏 = lost_forever
```

这样的单向 shortcut。

# 8. “在哪里”规则研究

失物定位目前至少有五套证据通道，不能揉成一个单一方向表。

## 8.1 内外卦 / 本宫他宫：近远层

证据状态：`stable_consensus`

《黄金策》《火珠林》《断易天机》《易隐》共同支持：

```text
内卦 / 本宫 / 静
→ 家中、近处、尚未远移的概率高

外卦 / 他宫 / 动
→ 外部、远处、已经移动的概率高
```

这是目前最适合成为第一层位置判断的传统证据。

## 8.2 爻位：空间层级

《黄金策》给出失物爻位取象，例如：

```text
五爻 → 道路
四爻 → 门户
六爻 → 梁阁 / 高处
初爻 → 井 / 低处等
二爻 → 灶附近
三爻 → 房中
```

这类规则有明确传统出处，但应理解为“位置取象”，不是现代 GPS 式坐标。

## 8.3 五行：环境材质层

《黄金策》等以财 / 用神五行推：

```text
水 → 池、水处
木 → 柴薪、木物附近
土 → 地面、土中
金 → 砖石、金石附近
```

可作为环境类型证据。

## 8.4 八卦宫：场所类型与方位层

《易隐》进一步以乾坤震巽坎离艮兑列出不同藏处场景。

这一层规则密度高、取象繁杂，和其他位置体系并不总能一一对应。

当前只能标为：

```text
school_specific / system_specific location evidence
```

不能直接压成一张唯一方位表。

## 8.5 墓、伏、合、所伏六亲：藏匿层

传统还通过：

- 入墓 / 化墓；
- 伏于何爻；
- 日辰合住；
- 所伏六亲；

判断：

```text
藏在容器中
衣箱 / 书箱
被覆盖
在某类人物 / 场所附近
```

这一层更适合解释“怎么藏着”，而不是单独给出方向。

# 9. recovery 与 location 是否属于同一规则

第一轮研究结论：**不能把两者当成完全同一条规则。**

原因有三层。

### 传统结构层

古典材料虽然常在一个“失脱”章节中讨论，但实际已经分别处理：

- 得失 / 见否；
- 在内还是在外；
- 藏在哪里；
- 是否被人移走；
- 是否是盗窃；
- 何时追获。

这些不是一个判断维度。

### 现代实践层

朱辰彬《古筮真诠·进阶篇》明确把：

```text
“钥匙丢哪儿了”
```

视为“现状卦”，重点看用神当前分布，不要求同时回答“最后能不能找到”。

而“手机还能不能寻回”的案例则直接判断结果趋势。

### 工程层

因此未来至少要允许：

```text
same lost object
↓
recovery assessment
location inference
```

成为两个不同输出职责。

是否在 Semantic 层最终做成两个 Route，还是同一事件下两个 `loss_goal`，留给后续 Semantic 设计阶段决定；本文不越权决定 Router Schema。

# 10. 现代物件映射初步结论

## 10.1 手机

现代来源中，朱辰彬明确把电话 / 手机作为父母类物件，并有“手机不见能否寻回”实占采用父母为用。

但当前证据只能支持：

```text
手机作为日常使用 / 通讯物件
→ 父母有直接现代实践支持
```

不能把它永久硬编码成：

```text
mobile_phone → 父母
```

如果用户问的是：

- 一台收藏保值的旧手机；
- 待转卖的商品库存；
- 纯粹以金额损失为核心；

其现实功能已经不同，需要另行研究。

## 10.2 证件 / 文书

古典直接支持父母，现代也一致。

这是目前现代映射中证据最稳的一类。

## 10.3 钥匙

朱辰彬现代案例取父母。

古典没有找到“钥匙”这一现代 / 具体物件的直接条目，因此目前属于：

```text
modern_mapping_only / compatible_with_parent-object tradition
```

## 10.4 首饰 / 戒指

朱辰彬案例提供了非常重要的反例：

```text
佩戴用品 → 父母
收藏保值 → 妻财
```

这说明对象名称不能脱离占问功能。

# 11. 与当前 Routes / 其他新主题的边界

## 11.1 receive_item

```text
“快递还没到”
```

如果只是延迟，没有明确遗失：

```text
receive_item
```

只有当前目标已经变成：

```text
包裹确认丢失，能否找回 / 在哪里
```

才进入 future `lost_property` 讨论。

## 11.2 item_purchase

```text
“这台手机值不值得买”
```

仍是购买问题。

物品本身相同，不等于事件相同。

## 11.3 financial routes

```text
“钱包丢了还能找回吗”
```

虽然对象具有财产价值，但当前目标是失物寻回，不应因为“钱”而自动改成 financial fortune / income route。

## 11.4 travel

旅途中丢东西：

```text
旅行 = 背景
失物寻回 = 当前目标
```

不自动进入 travel。

## 11.5 litigation_dispute

若用户问：

```text
东西被偷后报警 / 起诉能否追回？
```

需要区分：

- 当前目标是“物能不能回来”；
- 还是“诉讼 / 追责结果”。

诉讼是手段时不能仅凭背景词覆盖失物目标。

## 11.6 宠物 / 人员

传统资料本身就把：

```text
失物 → 财
六畜 / 飞禽走兽 → 子孙
逃亡 / 行人 → 另有体系
```

分开。

因此当前产品把宠物、儿童、家人、朋友排除出 `lost_property`，不仅是现代产品边界，也与传统分类本身相容。

# 12. 与 legacy 的冲突审计

当前最大冲突已经确认：

```text
Legacy:
所有高置信“失物 / 找东西” → 妻财

文献研究:
普通失物 → 妻财为稳定默认
但文书 / 证件等 → 父母有直接传统依据
舟车 / 衣服 / 用品 → 父母有传统和现代支持
动物 → 子孙（当前 route 排除）
现代复合物件还可能依功能变化
```

所以 legacy 的问题不是“妻财完全错”，而是：

> **把一个传统默认值错误提升成了无条件全类规则。**

后续正式设计必须改成：

```text
Lost Object
↓
Object Traditional Role Resolution
↓
Primary Observation
```

而不能继续：

```text
lost_property
↓
妻财
```

# 13. 当前不能建立的 shortcut

以下规则目前一律禁止直接进入正式 Rule Registry：

```text
失物 = 妻财（无例外）
手机 = 父母（无条件）
首饰 = 妻财（无条件）
空亡 = 永远找不到
入墓 = 永远找不到
伏神 = 永远找不到
官鬼出现 = 一定被偷
外卦 = 一定找不回
某一六神 = 固定方位
某一八卦 = 唯一实际地址
```

这些都把条件性传统规则压扁成了工程 shortcut。

# 15. 仍需继续研究的问题

本文件尚不能进入 `ready_for_rule_review`，至少还有以下缺口。

1. **物类映射表不完整**
   - 钱包、现金、银行卡；
   - 钥匙；
   - 手机、电脑、相机；
   - 首饰；
   - 证件；
   - 行李；
   - 商品库存；
   不能只凭现代直觉补齐。

2. **现代“功能优先”方法需要第二现代作者交叉验证**
   - 当前最明确的是朱辰彬；
   - policy 要求单一现代作者不能独立形成最终共识。

3. **朱辰彬扫描 PDF 需要页图复核**
   - p.120 类象表；
   - p.217 戒指案例；
   - 手机寻回案例；
   - 进阶篇钥匙定位案例。

4. **空亡 / 墓 / 伏的时间性尚未拆清**
   - 哪些表示暂时不可见；
   - 哪些表示难寻；
   - 哪些可待冲墓 / 出空；
   - 不能触碰当前已冻结 Time Engine，需只形成失物专项证据接口。

5. **位置规则冲突尚未做矩阵**
   - 爻位；
   - 五行；
   - 地支方位；
   - 八卦宫；
   - 六神；
   - 墓伏；
   多通道同时出现矛盾时，传统来源如何处理仍需继续搜证。

6. **被盗 / 自失 / 被人拾取需要独立结构**
   - 目前证据很多；
   - 但它们属于 `loss_context` 还是另一个传统 Domain Observation，需要后续决定。

7. **“找物”与“抓贼”边界需要正式固定**
   - 古籍常合章；
   - Semantic 不能因此合并现实目标。

# 16. 当前研究结论

第一轮最重要的结论不是“失物应该改成父母”，而是：

> **“失物”不能直接映射到一个固定六亲。普通失物以妻财为稳定传统默认，但古典本身已经要求按物类通变；文书、证件等父母类对象有直接传统依据，现代复杂物件还需要按实际功能继续映射。**

同时：

> **“能否找回”与“在哪里”共享同一个失物本体，但不是同一判断职责。前者偏向得失、旺衰、世用与显隐；后者更多读取内外、爻位、五行、卦宫、墓伏与遮藏信息。**

这意味着 future `lost_property` 的传统层至少不能是：

```text
lost_property
→ 妻财
→ buildUseGodAnalysis()
```

更合理的待研究结构是：

```text
Lost-property semantic event
↓
Object traditional-role resolution
↓
Primary lost-object observation
↓
Recovery / Location 分职责读取
↓
盗窃、自失、拾取等条件性辅助观察
```

但当前仍保持：

```text
research_in_progress
not_ready_for_rule_review
trainingEligible = false
currentRoute = false
```

不得据本文件直接修改 Rule Registry 或 Semantic Candidate。
