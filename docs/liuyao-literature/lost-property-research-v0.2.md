# 龟甲 · 六爻失物主题文献研究 v0.2

日期：2026-08-31

状态：`research_in_progress`

研究主题：`lost_property`

> 本文件承接 v0.1，继续作为文献研究稿。它不是正式 Observation Rule，不修改当前 22-route Semantic Candidate，不修改 Rule Registry，不修改 Time Engine。
>
> v0.2 的重点是：补入第二位现代作者王虎应，确认现代物件取用存在真实分歧；把“能否找回”与“在哪里”进一步拆成不同判断职责；建立第一版位置证据通道矩阵。

---

## 1. 当前研究结论摘要

目前已经可以确定四件事：

1. **普通失物以妻财为默认主观察对象，属于跨古典来源稳定规则。**
2. **失物并非无条件一律取妻财；文书、证件、舟车、衣服等存在按物类切换父母的直接传统依据。**
3. **“能否找回”与“失物在哪里”共享同一个失物本体，但不是同一判断职责。**
4. **现代手机、钥匙、戒指等不能按物品名称直接硬编码六亲。**现代作者之间已经出现实质分歧，尤其手机取用并无现代共识。

因此当前 legacy：

```text
lost-item → 妻财
```

只能保留为历史 heuristic，不能直接晋升正式 Observation Rule。

---

## 2. 研究范围

当前只研究无生命财物的：

```text
lost_property_recovery
→ 某件已经遗失的物品能否找回

lost_property_location
→ 某件已经遗失的物品现在在哪里
```

继续排除：

- 宠物、家畜、飞禽走失；
- 儿童、亲友、其他人员失踪；
- 尚未确认遗失的物流运输；
- 物品购买适合性；
- 独立的抓贼、追赃、盗贼身份目标。

古籍往往把“失物 / 是否被盗 / 贼是谁 / 捕盗 / 所在位置”放在同一篇中，现代 Semantic Route 必须重新拆分。

# 3. 来源与证据层级

## 3.1 CL-HPZL：《火珠林》

古典原始 / 早期体系来源。

直接证据包括：

- “逃亡看世，失物看财”；
- 普通失物看财；
- “若失文书牌号，当以父母爻取”；
- 六畜另看子孙；
- “凡失物专看财爻”；
- 父母为衣服、文书，财为失物；
- 财在内卦安静旺相，可指物尚在家中。

这部文献同时证明了两个容易被误合并的命题：

```text
普通失物默认看财
≠
所有失物无条件看财
```

---

## 3.2 CL-HJC：《黄金策·失脱》

古典核心分类占法。

核心证据：

- “要识其中之得失，须详卦上之妻财”；
- 自空、化空与日月旺衰参与得失判断；
- 内卦 / 本宫与家庭近处，外卦 / 他宫与外部位置相关；
- 初至六爻分别对应不同空间层级；
- 五行用于推测藏处环境；
- 动入墓、日辰合住、伏神等参与“藏在哪里”的判断；
- “静临世上，物尚在”；
- “鬼兴出现”作为被盗线索；
- 篇末明确指出“舟车衣服”与“走兽飞禽”不能机械套普通规则。

这里已经形成至少三种不同职责：

```text
失物本体是谁 → 取用
能否找回      → 得失 / 旺衰 / 空破 / 世用等
在哪里        → 内外 / 爻位 / 五行 / 墓合伏等
```

---

## 3.3 CL-DYTJ：《断易天机·占遗失第十七》

古典体系化来源。

继续支持：

- 遗失占以财爻为主线；
- 财化鬼、鬼化财；
- 财空、入墓；
- 内财静 / 外财动；
- 六畜另取子孙。

本轮暂未增加新的独立现代映射结论。

---

## 3.4 CL-YY：《易隐》卷八

后世体系化 / 分类细化来源。

其价值在于把不同职责拆得更细：

- “拾者”；
- “知情”；
- “见否”；
- 位置；
- 追获时间。

这进一步说明不能用一个单一 `lost_property_result` 把所有传统判断压成一个结论。

---

## 3.5 CL-BSZZ：《卜筮正宗》

后世整理 / 注释体系。

注意：与《黄金策》失脱篇存在明显承接关系，证据统计时不得把两者机械当作完全独立来源。

其重要价值是把物类分流解释得更明确：

```text
舟车、衣服、文书券契 → 父母
飞禽走兽             → 子孙
普通财物             → 妻财
```

---

## 3.6 MOD-ZCB：朱辰彬《古筮真诠》《古筮真诠·进阶篇》

现代实践来源。

用户提供的扫描 PDF 已可直接读取。当前找到的重点材料包括：

- 父母爻类象中包含车船、衣服、电话、物件、证件等；
- 寻戒指案例中，若戒指作为日常用品则取父母；若作为收藏 / 保值财物，则可按财物处理；
- 手机遗失实例以父母爻取用；
- 钥匙“丢哪儿了”的案例强调“在哪里”属于现状信息，与最终能否找到不是同一判断层；
- 动物遗失仍按子孙，和古典六畜规则相合。

朱辰彬体系的明显倾向是：

```text
现代物品不能只按价值判断，
需要看物品在本次占问中的现实功能。
```

---

## 3.7 MOD-WHY：王虎应《六爻预测自修宝典》

现代体系化来源。

本轮新增的重要来源。

其“第二十七章 预测失物”明确提出：

```text
书籍、信件、证书、车、衣服等 → 父母
日用品、钱、贵重东西          → 妻财
```

同时给出多个实际案例：

- 自行车遗失：父母为用，兼看财；
- 钱遗失：妻财为用；
- 移动电话遗失：**妻财为用**；
- 位置判断：使用用神地支、卦宫、伏神 / 飞神、五行、内外卦、墓合、爻位等。

王虎应也提出：

```text
若本体用神为父母，仍可兼看妻财的衰旺来判断失物可否找回。
```

这是一种值得单独保留的“双层观察”思路，但目前属于现代作者体系，不得反推为古典共识。

# 4. 取用研究 Findings

> 以下仍是 Research Finding，不是正式 Rule Candidate ID。

## LP-RF-001：普通失物以妻财作为默认主观察对象

证据状态：`stable_consensus`

来源：

- 《火珠林》；
- 《黄金策》；
- 《断易天机》；
- 《易隐》。

研究结论：

```text
generic lost possession
→ 妻财作为默认传统入口
```

“默认”是关键字，不得改写为“所有”。

---

## LP-RF-002：失物取用按物类分流

证据状态：`stable_consensus`

古典直接可支持：

```text
普通财物 → 妻财
文书牌号 / 文书券契 → 父母
舟车 / 衣服 → 父母
六畜 / 飞禽走兽 → 子孙
```

对龟甲当前 `lost_property` 而言，最后一类应被 Semantic Boundary 排除，而不是进入失物无生命财物规则。

---

## LP-RF-003：文书、证件类失物取父母可进入高置信候选

证据状态：`stable_consensus`

传统文书、牌号、券契与现代：

- 纸质证件；
- 合同原件；
- 票据；
- 证明文件；

之间具有较强功能连续性。

但电子文件、云端数据仍属于现代映射问题，当前不自动扩张。

---

## LP-RF-004：舟车、衣服等具体用品可取父母

证据状态：`cross_source_compatible`

古典层已经直接支持舟车、衣服。

现代作者都承认“车、衣服”可按父母，但对于更广泛的现代日用品并未形成统一边界。

因此：

```text
传统明确列举的物类
```

可以高置信；

```text
现代扩展出来的“所有日常用品”
```

不能直接提升为古典共识。

---

## LP-RF-005：手机取用存在现代作者直接冲突

证据状态：`conflicted`

### 朱辰彬

手机 / 电话作为日常物件，在其类象和寻物实例中取父母。

### 王虎应

《六爻预测自修宝典》“移动电话丢失”实例明确：

```text
以财爻为用神
```

且其失物总则把“日用品、钱、贵重东西”归妻财。

因此：

```text
手机 = 父母
```

和

```text
手机 = 妻财
```

都不能作为跨现代作者共识。

工程结论：

> **禁止建立 objectType=phone → 固定六亲 的硬编码。**

手机必须暂时进入需要语义功能判定或保留分歧的现代映射层。

---

## LP-RF-006：现代物件的“功能取用”有解释力，但目前仍非稳定共识

证据状态：`school_specific / cross_source_partial`

朱辰彬的戒指例非常清楚地展示：

```text
同一对象名称
+ 不同现实用途
→ 可改变取用
```

但王虎应采用的分类更接近：

```text
用品 / 钱 / 贵重物 → 财
车 / 衣 / 文书 → 父母
```

两者并非完全等价。

因此当前最安全的 formalization 不是直接采用朱辰彬的全部功能模型，而是：

```text
第一层：传统明确物类规则
第二层：现代映射规则（允许作者分歧）
第三层：若现代物件无法稳定映射，则 unresolved / provisional
```

---

# 5. “能否找回”与“在哪里”必须分层

## LP-RF-007：Recovery 与 Location 是不同判断职责

证据状态：`stable_consensus`

《黄金策》在同一篇内分别提供：

- 得失 / 是否可寻；
- 家内家外；
- 爻位；
- 五行环境；
- 墓、合、伏等藏处；
- 是否被盗。

朱辰彬“钥匙丢哪儿了”的现代案例又明确把“在哪里”作为现状层读取。

所以 Observation / Assessment 设计上至少应分为：

```text
Primary Object Observation
→ 失物本体

Recovery Assessment
→ 是否有找回条件

Location Evidence
→ 位置线索
```

Location Evidence 不应反向决定 Primary Object 的六亲。

# 6. Recovery 第一版证据整理

目前跨来源重复度较高的判断维度包括：

## 6.1 旺衰 / 空破

《黄金策》：自空、化空与日月旺衰直接进入“得失”判断。

《火珠林》：财爻旺相、不空、不动倾向可见；空、动、无气则难寻。

王虎应：用神宜旺，不宜空破。

候选状态：`cross_source_compatible`

---

## 6.2 内外 / 动静

《火珠林》：财在内卦安静旺相，物不失、在家中。

《黄金策》：内卦本宫与家庭，外卦他宫与外部相连。

王虎应：用神在外卦则偏向外部 / 远处；用神安静较易找，发动较难找。

其中：

```text
内外 → 位置远近 / 家内外
```

跨来源较稳定；

```text
动必难找 / 静必易找
```

仍需逐条比较条件，暂不升级为硬规则。

---

## 6.3 世用关系

《黄金策》有“静临世上，物尚在”等直接关系。

王虎应明确提出：

```text
世克用 → 难找
用克世 → 易找
```

但这一表达目前主要来自现代体系，古典是否具有完全相同的通则措辞还需继续核证。

状态：`insufficient_evidence_for_general_rule`

---

## 6.4 伏神 / 墓 / 合

多个来源均把它们用于：

- 是否隐藏；
- 被遮掩；
- 藏在器物内；
- 一时不见；
- 位置线索。

但具体“何状态一定可回 / 不可回”存在体系细节差异。

因此目前适合建立 Evidence，不适合直接压成单一 Boolean Rule。

---

# 7. Location 第一版证据通道矩阵

位置判断目前不应实现为一个单一公式，而应拆成多条证据通道。

| Evidence Channel | 《火珠林》 | 《黄金策》 | 王虎应 | 当前评价 |
|---|---|---|---|---|
| 内卦 / 外卦 | 有 | 有 | 有 | `stable_consensus` |
| 本宫 / 他宫 | 有相关体系 | 有 | 卦宫参与 | `cross_source_compatible` |
| 爻位 1–6 | 有局部 | 明确 | 明确建议结合 | `cross_source_compatible` |
| 五行藏处 | 有 | 明确 | 明确 | `stable_consensus` |
| 地支方位 | 有 | 可结合 | 明确 | `cross_source_compatible` |
| 八卦宫象 | 有 | 有相关结构 | 明确使用 | `cross_source_compatible` |
| 墓 | 有相关 | 明确 | 明确 | `stable_consensus_as_location_evidence` |
| 合 | 有相关 | 日合遮藏 | 器物内 / 合处 | `cross_source_compatible` |
| 伏神 / 飞神 | 有 | 明确 | 明确 | `stable_consensus_as_hidden-location-evidence` |
| 六神 | 有类象体系 | 失脱篇使用六神描述盗贼等 | 有 | `school_sensitive` |
| 卦名 / 卦辞象 | 零散 | 非主轴 | 王虎应案例会使用 | `school_specific` |

关键工程原则：

> **Location 应输出多通道证据，不应把所有信息转换成一个“东南 3 米处”的伪精确结果。**

# 8. 古典位置证据中较稳定的部分

## LP-RF-008：内外卦是最稳定的位置粗分层之一

证据状态：`stable_consensus`

可先作为：

```text
inside / near / home-side
vs
outside / farther / external-side
```

的粗粒度 Evidence。

但“内卦一定在家”仍需结合占问上下文，不应脱离语境机械化。

---

## LP-RF-009：五行环境可以作为位置类象，不是字面 GPS

证据状态：`stable_consensus_as_symbolic_evidence`

《黄金策》直接以水、木、土、金等对应池、水边、柴薪、地、砖石等藏处。

王虎应同样用：

- 木 → 草木 / 木器；
- 水 → 水边；
- 土 → 土堆；
- 金 → 金属物附近；
- 火 → 炉灶等。

这些应作为：

```text
location_environment_evidence
```

而不是确定坐标。

---

## LP-RF-010：墓、合、伏可统一抽象为“隐藏 / 被容纳 / 非显露位置”的 Evidence，但不能抹平原规则差异

证据状态：`cross_source_compatible`

例如：

- 入墓 → 深藏 / 仓储 / 容纳；
- 合住 → 遮盖 / 包裹 / 器物中；
- 伏神 → 不显露、被压在其他事物之下。

正式建模时建议保留原始 fact：

```text
in_tomb
joined
hidden_as_fushen
```

上层再映射：

```text
hidden_or_contained
```

禁止只保存一个模糊“藏起来了”。

# 9. 盗窃线索与 lost_property 的边界

古籍大量使用官鬼分析：

- 是否被盗；
- 贼之男女；
- 内外勾连；
- 是否能捕获。

但当前 `lost_property` 只需要在恢复判断中允许：

```text
loss_cause_evidence = possible_theft
```

不能自动把：

```text
官鬼出现
→ 开启盗贼身份推理
```

因为“找回物品”与“谁偷的”不是同一个现代目标。

若未来建立 theft / offender route，应另做 Semantic 与传统规则研究。

# 13. 与当前仓库 legacy 的冲突审计

当前 legacy：

```text
lost-item → 妻财
```

审计结果：

```text
普通财物：得到传统支持
文书 / 证件：过度泛化，需分流父母
车辆 / 衣服：过度泛化，需分流父母
手机：不能仅靠 legacy 判妻财，也不能统一改父母；现代资料存在冲突
现代其他物件：需按研究成熟度逐类处理
```

所以未来不能简单做：

```diff
- lost-item → 妻财
+ lost-item → 父母
```

这只会从一种错误泛化换成另一种错误泛化。
