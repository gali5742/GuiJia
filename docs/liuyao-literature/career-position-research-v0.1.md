# 1. 现代问题范围

依据 `data/liuyao-next-topic-inventory-v0.1.json`，当前研究先围绕三个现代职责假设展开：

```text
job_application_outcome
→ 某个具体求职 / 面试 / 录用 / 入职结果

position_advancement
→ 某个具体升职 / 晋升 / 转正 / 职位上升结果

employment_transition_decision
→ 是否去某个新单位 / 是否从当前岗位转去另一份工作
```

第一阶段暂不把下列宽泛问题直接视为可训练 route：

```text
事业怎么样
职业发展如何
以后工作好不好
```

原因不是传统上无法占，而是现代 Semantic Target 过宽，可能同时包含职位、单位、收入、稳定性、人际、地点等多个职责。若没有更明确的 current target，直接归入 `career_position` 会掩盖多目标或信息不足问题。

明确边界：

- 工资 / 薪酬金额为当前目标 → `income_salary`；
- 奖金 / 绩效发放为当前目标 → `income_bonus`；
- 某公司、上司、同事仅作为背景 → 不自动构成事业 route；
- 工作带来的财务收益不是 `financial_fortune` 的当然替代；
- 公务员、资格、招聘考试若当前问题是“考试是否通过 / 排名” → 后续与 `study_exam` 边界裁决；
- 若当前问题是“最终能否获得该职位” → 才可能落入 `career_position`。

# 2. 古典占类对应

现代事业职位问题与古典至少存在三条不同传统链：

## 2.1 求仕

核心是“能否求得官职 / 任命”。

《卜筮全书·求仕章》明确以官鬼为求官核心，并把父母作为宣敕、任命文书的重要观察对象。

该类与现代：

```text
求职
应聘职位
能否被录用
```

存在结构连续性，但不能直接认定现代私人雇佣等于古代求官；现代映射仍需单独核证。

## 2.2 仕宦

核心是已经任职后的：

- 官位高低；
- 升迁；
- 在任安否；
- 俸禄；
- 除授 / 宣敕；
- 降职 / 去职。

《黄金策·仕宦》以官鬼为官爵，以妻财为俸禄，以父母为差除宣敕，并持续观察世爻与官爻关系。

该类与现代：

```text
升职
晋升
转正
职位稳定
```

连续性较高。

## 2.3 求名

《黄金策·求名》把父母与官鬼并列为核心：父母对应文章 / 文书，官鬼对应功名 / 官职。

这一传统更接近：

- 科举；
- 招考；
- 选拔；
- 名次；
- 通过考试获得身份 / 职位。

因此它是 `career_position` 与 `study_exam` 的重要碰撞区，不能因为最终可能得到职位，就把所有考试一律归入事业。

# 3. 来源目录与独立性审计

## 3.1 传统来源

第一轮已核：

1. 《断易天机》：求官、迁官、加官、现任等条目；
2. 《卜筮全书》：求仕章、黄金策体系；
3. 《黄金策》：求名、仕宦；
4. 《增删卜易》：功名、升迁、现任官卦例与总则；
5. 《易隐》卷六：求官、在任、升迁等体系。

独立性注意：

- 《黄金策》被《卜筮全书》《卜筮正宗》等大量收录、解释，不能把同一段传统机械计算成多份独立证据；
- 《增删卜易》可作为较独立的实践传统对照；
- 《断易天机》与《易隐》可提供不同历史层次的结构对照。

## 3.2 现代来源

第一轮已核：

6. 王虎应《六爻预测自修宝典》第二十九章“预测工作”及相关用神答疑；
7. 朱辰彬《古筮真诠》《古筮真诠·进阶篇》中的求职、职位竞聘、工作前程、单位内晋升、指定单位工作等案例。

现代来源目前已经达到至少两位独立作者，但具体命题仍需逐项判断，不因为“两个作者都谈过工作”就自动升级为现代共识。

# 4. 第一轮逐条证据与研究判断

## CP-RF-001 官鬼作为“工作 / 官职 / 职位”核心观察具有稳定传统连续性

支持类型：`stable_consensus`

传统证据链：

- 《断易天机》求官条以官鬼得失判断能否得官，并单列迁官、加官；
- 《卜筮全书·求仕章》明确“凡卜求官，官鬼是用爻”；
- 《黄金策·仕宦》以官鬼表示官爵与升迁；
- 《增删卜易》序及升迁卦例持续以官星、官鬼为功名升迁核心；
- 《易隐》升迁体系持续观察“世官”。

现代连续性：

- 王虎应明确把一般工作、找工作、升职、工作变动的主用神放在官鬼；
- 朱辰彬大量“工作前程”“升迁”“找工作”实例也以官鬼为工作 / 职位核心。

当前可成立：

```text
employment / position as the current target
→ 官鬼具有高成熟度 Primary 候选资格
```

但这还不能推出：

```text
任何提到公司 / 面试 / 跳槽的问题
→ 一律只看官鬼
```

---

## CP-RF-002 世爻是求职者 / 任职者本人，不应被官鬼吞并

支持类型：`stable_consensus`

传统资料在求官、升迁、仕宦中反复使用：

```text
官鬼
↔
世
```

来判断职位与本人之间的生合、冲克、持世等关系。

因此架构上更合理的职责分离是：

```text
Primary Observation
→ 官鬼 / 职位本体

Role Observation
→ 世 / 求职者或任职者本人
```

不能因为“官鬼持世”常为一体，就把 `世` 从 Observation Plan 中删除。

---

## CP-RF-003 父母在古典中稳定代表任命文书 / 印绶，但“现代公司单位 = 父母”属于现代扩展

传统部分支持类型：`stable_consensus`

现代单位映射支持类型：`cross_source_compatible`

传统来源：

- 《卜筮全书·求仕章》把父母作为宣敕 / 任命文书，并称官鬼、父母为占官根本；
- 《黄金策·仕宦》明确关注“父母空亡”与差除宣敕；
- 《断易天机》求官条把父母解释为诰牒任命书。

这些传统材料足以支持：

```text
appointment_document / formal authorization
→ 父母
```

但古代“父母 = 宣敕 / 印绶”不能无缝等同现代：

```text
company / employer / organization
→ 父母
```

现代映射证据来自：

- 王虎应：官鬼为工作，父母为工作的公司 / 单位；
- 朱辰彬：有明确单位的工作，父母可代表单位，官鬼代表工作 / 职位。

因此“单位 = 父母”目前是**现代跨作者兼容映射**，不是直接古典同义关系。

---

## CP-RF-004 “指定单位求职”存在官鬼 / 父母双候选，不能由关键词单独决定

支持类型：`cross_source_compatible`

朱辰彬《古筮真诠》职位竞聘例明确指出：

```text
明确单位或职位的应聘
→ 可取单位父母
→ 也可取职位官鬼
```

其判断强调事主实际关注点。

《古筮真诠·进阶篇》“进入省农业银行工作”例进一步讨论：指定单位求职时，父母与官鬼都可能成为候选，需要辨别实际问念。

王虎应则把两者职责拆为：

```text
官鬼 = 工作
父母 = 公司 / 单位
```

两位现代作者的共同点不是“永远选同一个爻”，而是：

```text
job / position
与
employer / unit
是两个不同传统观察语义
```

因此现代 Semantic 层至少应保留：

```text
employment_target
```

并区分：

```text
position-focused
employer-focused
```

当前不能提前决定最终 Observation Rule 是：

- 二选一 resolver；
- 一个 Primary + 一个 Domain；
- 复合 Primary；
- 或按不同 route 拆分。

这需要后续专项规则审查。

---

## CP-RF-005 升职 / 晋升以官鬼为核心，成熟度高

支持类型：`stable_consensus`

传统支持：

- 《断易天机》单列“迁官”“加官”；
- 《黄金策·仕宦》直接讨论爵位升迁；
- 《增删卜易》有多条自占升迁实例，以官鬼为核心；
- 《易隐》卷六单列“升迁”。

现代支持：

- 王虎应明确“测升职”观察官鬼与世；
- 朱辰彬“职务升迁”“单位内晋升机会”等实例均以官鬼作为职位核心。

因此：

```text
position_advancement
→ 官鬼 Primary 候选成熟度高
→ 世作为 Role Observation
```

父母在其中更可能承担任命、手续、单位或正式确认的辅助 / Domain 职责，而不是当然取代官鬼。

## CP-RF-006 妻财在仕宦传统中可代表禄俸，但工资目标必须与事业职位职责分离

支持类型：`stable_consensus`（传统角色） + `modern_mapping_only`（路由边界）

《黄金策·仕宦》把妻财与俸禄联系；王虎应现代工作章也以妻财观察工资。

所以传统上：

```text
career context
→ 妻财可作为 compensation evidence
```

但在龟甲现代 Semantic Stack 中：

```text
“能不能升职”
→ career_position

“工资能涨到多少 / 能否发工资”
→ income_salary
```

不能因为仕宦篇同时讨论“禄”，就把现代薪资 route 吸收到事业 route。

## CP-RF-007 求职考试 / 公务员考试是 `career_position` 与 `study_exam` 的真实边界，不可按“考试”或“工作”关键词优先

支持类型：`stable_consensus`（传统职责分离） + `modern_mapping_only`（现代路由边界）

《黄金策·求名》与《卜筮全书》求名体系本来就把：

```text
父母 = 文章 / 文书
官鬼 = 功名 / 官职
```

并列观察。

王虎应现代资料进一步指出：

- 求职考试、职称评定考试可参考考学方法；
- 一般工作则以官鬼为工作；
- 求职考试中官鬼与父母都可能成为观察核心。

朱辰彬公务员考职案例则把“考职成功”与“是否进入指定单位”继续拆开。

因此后续 Semantic Boundary 应按**当前目标**裁决：

```text
“这次笔试能不能通过？”
→ exam outcome 倾向 study_exam

“最后能不能被这个职位录用？”
→ employment outcome 倾向 career_position

“笔试第二，最后面试能否获聘？”
→ 已从考试表现转入职位获得结果，倾向 career_position
```

此结论仍需在 `study_exam` 研究完成后做跨主题冲突矩阵复核。

## CP-RF-008 工作变动 / 跳槽不能仅用“官鬼旺衰”表达，当前岗位与目标岗位需要结构化区分

支持类型：`cross_source_compatible`

王虎应现代体系明确提出：

```text
工作变动
→ 世爻：现在的工作环境
→ 应爻：要去的地方
```

其用神答疑中的跳槽实例仍以官鬼判断新工作能否成立，并允许新旧工作在卦中以不同官鬼 / 变爻表现。

《易隐·升迁》则有：

```text
内旺外衰 → 宜守旧
内衰外旺 → 宜图新
```

这说明传统工作 / 官职变动并非只有单个官鬼强弱，而有“当前—新处”的比较结构。

但需要特别注意：

- 王虎应的“世 = 当前工作环境、应 = 新工作地点”是现代体系规则；
- 《易隐》的内外比较属于古典升迁系统；
- 两者可以兼容，但不能直接证明一个跨流派固定公式。

因此 `employment_transition_decision` 暂不能登记为：

```text
Primary = 应
```

或：

```text
Primary = 官鬼
Role = 世 / 应
```

哪种结构更合适仍需继续研究。

## CP-RF-009 “事业前程”在传统上可取官鬼，但现代 Routeability 仍可能信息不足

支持类型：`cross_source_compatible`

朱辰彬多例“工作前程 / 事业前景”直接以官鬼为用神；王虎应“预测工作”也以官鬼为工作核心。

但现代自然语言：

```text
我的事业以后怎么样？
```

并没有说明究竟在问：

- 是否继续当前岗位；
- 能否升职；
- 是否跳槽；
- 收入；
- 稳定性；
- 单位环境；
- 职业方向。

所以：

```text
traditional_observation_possible
≠
semantic_route_sufficient
```

这是本主题必须保留的硬边界。

# 7. 当前禁止捷径

现阶段禁止形成以下实现：

```text
事业 → 官鬼
面试 → 官鬼
公司 → 父母
跳槽 → 应爻
升职 → 官鬼旺 = 必升
子孙动 → 必失业
```

尤其禁止把现代 Entity Typing 直接输出传统六亲。

正确层次仍然是：

```text
现代自然语言
↓
current target / event / participants
↓
career semantic responsibility
↓
traditional rule selection
↓
Observation Plan
```

# 9. 下一轮研究问题

在进入 Rule Candidate 前至少还需解决：

1. **指定单位求职**到底应使用“官鬼 Primary + 父母 Domain”，还是允许真正的 Primary Resolver；
2. **面试 / offer / 入职**三个阶段在传统职责上是否需要拆分；
3. **转正**更接近升迁、求仕，还是“父母正式任命 + 官鬼职位”的复合结构；
4. **跳槽 / 留任选择**中的世、应、新旧官鬼如何形成可跨来源复核的结构；
5. **裁员 / 保住工作**是否进入本主题首批 route，还是作为以后单独 `employment_retention`；
6. 与 `study_exam` 完成双向边界核验；
7. 对“兄弟 = 竞争者”“子孙 = 剥官 / 失职风险”只建立 Evidence 条件，不允许关键词式绝对判断；
8. 继续核对现代第二作者在指定单位、面试、跳槽中的完整案例，避免只引用总论句。

# 10. 第一轮结论

目前最稳固的部分不是“事业都看官鬼”，而是：

```text
职位 / 工作本身 → 官鬼
本人 → 世
任命文书 → 父母
薪酬 → 妻财
```

真正困难的是现代职业场景增加了“公司 / 单位”这一独立对象。两位现代作者都把单位与工作本身区分开，且都允许父母承担单位语义；因此：

```text
job / position
≠
employer / organization
```

必须进入龟甲的 Semantic / Observation 职责设计。

本主题当前仍保持：

```text
research_in_progress
trainingEligible = false
currentRoute = false
formal Observation Rule = missing
```
