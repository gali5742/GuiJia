# 龟甲 v13.44.0-alpha.9 · 剩余并列分型审计

## 目标

在 alpha.8 Structural Relevance 之后，不再立即追加日期排序规则，而是先审计剩余并列究竟来自：

1. 当前 comparator 把六维信息压得过粗；
2. 当前 comparator 过早剪掉了本应保留的多维权衡日期；
3. 真正需要新增术数原则才能决定的不可比关系；
4. 当前模型下本来就完全等价的日期。

本阶段只做开发审计，不修改生产 comparator，不切换正式页面与「复制分析上下文」。

## 诊断方法

新增 `scripts/review-liuyao-selection-ties.mjs`。

诊断基准使用六维非补偿 Pareto：

- 生扶、比和分别保留；
- 泄力、耗力分别保留；
- 受制继续作为硬负担层；
- 不给任何维度换算数值权重；
- material 完全相同时继续沿用 alpha.8 Structural Relevance 细化。

这套“细粒度六维 Pareto”只用于比较 alpha.8 coarse benefit/cost 选择行为，不进入正式用户结果。

## 4096 卦审计结果

固定问题：`这周哪天适合出行`。

- 有效卦数：4096
- schema / 运行异常：0
- alpha.8 单一第一候选：1641（40.06%）
- alpha.8 剩余并列：2455（59.94%）
- 六维细粒度诊断单一第一候选：1368（33.40%）
- 六维细粒度诊断仍并列：2728（66.60%）
- 第一前沿完全一致：3234（78.96%）
- 六维诊断是 alpha.8 严格子集：258（6.30%）
- alpha.8 是六维诊断严格子集：604（14.75%）
- 两套前沿互有增删：0
- alpha.8 并列 → 六维诊断单选：255
- alpha.8 单选 → 六维诊断并列：528
- 两边都并列但集合变化：79
- 六维诊断后剩余并列已分型：2728 / 2728
- 未分类：0

因此 alpha.8 的 coarse benefit/cost 聚合并非单纯“分辨率不足”：它同时会遗漏已有六维支配关系，也会过早剪掉六维上互有长短的日期。

## 剩余并列主要类型

诊断后的并列原因可全部解释，主要包括：

- 纯生扶 vs 纯比和：1862 卦；
- 效力与结构相关性完全同质：618 卦；
- 纯泄力 vs 纯耗力：170 卦；
- 额外助力 vs 额外软负担：272 卦；
- 有助有负担 vs 仅软负担：332 卦；
- 双方都有助有负担的交叉权衡：6 卦。

同一卦可能同时命中多个分型，因此上述原因计数不要求相加等于总并列数。

## 结论

1. 下一步若继续调整日期选择，不应继续给 `hasBenefit / hasSoftCost` 这层 coarse comparator 打补丁。
2. 更一致的方向是让正式 Candidate Date Selection 直接使用六维非补偿 Pareto，再由 Structural Relevance 只处理 material 完全相同的日期。
3. 这不会自动解决“生扶 vs 比和”“泄力 vs 耗力”，这些仍是显式术数边界；没有明确原则时保留并列。
4. 完全同质日期继续视为真正等价，不为了降低并列率强行决胜。
5. 本阶段不实施上述 comparator 替换，只把问题范围与风险定清。

## 用户接口

无变化。页面、复制分析上下文、时间解析、KeyLine 与关键节点筛选全部继续使用 alpha.8 之前的正式路径。
