## 部署前本地检查

无需安装 npm 依赖：

```bash
npm run predeploy
```

该命令会检查：

- 八字 / 六爻核心回归测试；
- 固定依赖版本策略；
- GitHub Actions / Dependabot 必需配置；
- HTML 引用的本地静态资源是否存在；
- 是否出现未经允许的远程可执行脚本。

## GitHub Pages 发布方式

本版本使用 **GitHub Actions**，不要选择旧的 `Deploy from a branch`。

首次上传仓库后：

1. 打开 `Settings → Pages`；
2. 将 Source 设为 **GitHub Actions**；
3. 确认仓库默认分支为 `main`；
4. Actions 中的 `Test and vendor verification` 通过后，再运行/等待 `Deploy GitHub Pages`；
5. 首次正式发布前，建议手动运行一次 `Vendor Snapshot PR`，审核并合并生成的 vendor 快照。

详细步骤见 `docs/DEPLOYMENT_CHECKLIST.md`。

## JavaScript 结构

- `js/common.js`：日期、时间、真太阳时修正与八字/六爻共用的上下文格式化工具
- `js/iching-loader.js`：《周易》经文的本地 / 缓存 / 远程三级读取
- `js/bazi-core.js`：八字静态规则、五行十神、干支关系与结构计算
- `js/bazi-timing.js`：大运、流年、流月数据组装，节令流月范围与年份定位
- `js/bazi-literature.js`：八字古籍索引与 matcher
- `js/bazi-interpretation.js`：八字原局结构解释与复制分析上下文
- `js/bazi-detail.js`：八字详细分析页的数据整理，展开强弱证据、十神透藏、月令显隐、关系网络与古籍条件对照
- `js/liuyao-time-facts.js`：六爻目标时间纯事实层（TimeFact）
- `js/liuyao-time-effects.js`：TimeFact → 六维 TimeEffect 映射层
- `js/liuyao-time-assessment.js`：六维 TimeEffect → Node Assessment 节点聚合层
- `js/liuyao-time-evidence.js`：Node Assessment → Evidence Selector 证据绑定、结构化包含去重与覆盖校验层
- `js/liuyao-time-relevance.js`：把 Node Assessment 的来源角色映射为结构相关性层级；用于同质日期的触发重要度细化，不改变六维实质效力。
- `js/liuyao-time-output.js`：Time v2 用户输出层；生成节点摘要、日期判断与证据文案
- `js/liuyao-time-selection.js`：日期选择的受制硬门槛、六维非补偿 Pareto 前沿与同质日期结构相关性细化；alpha.10 起冻结判断原则。
- `js/liuyao-time-review.js`：历史开发期影子对照模块；v13.44.0 正式站点不再加载，也不打入 Pages 部署产物，仅保留源码用于历史回归。
- `js/liuyao-core.js`：六爻八宫、纳甲、日月状态、动变、用神与应期核心函数
- `js/liuyao-literature.js`：六爻古籍条目与结构 matcher
- `js/app.js`：Vue 状态、页面导航、选择状态与两套排盘流程编排；不再直接组装岁运领域数据

## v13.44.0-rc.1 · Time v2 语义收口 RC

本阶段不再增加时间规则，只修 beta.3 手测确认的两个阻断实现错误。

## v13.44.0-alpha.10 · 时间效力模型重构 · 第 10 步

本阶段主题：**六维 Date Selection 正式重构与判断原则冻结**。

- `js/liuyao-time-selection.js` 不再把生扶/比和压成 `hasBenefit`、把泄力/耗力压成 `hasSoftCost`；同一受制层级内直接按四个独立实质维度执行非补偿 Pareto。
- 受制继续作为硬门槛：存在未受制候选时，受制日不能通过其他有利维度补偿后进入第一前沿。
- 生扶、比和分别保留为独立有利维度；泄力、耗力分别保留为独立负担维度。多一种助力同时多一种负担时视为真实权衡，保留并列。
- Structural Relevance 只在实质效力完全相同的日期之间细化，不跨六维边界重新排序。
- 4096 卦一周选日中，生产 comparator 与独立六维诊断第一前沿 **4096 / 4096 完全一致**；单一候选 1368（33.40%），并列 2728（66.60%），未分类并列 0。
- 4096 卦“明天还是周五哪个好”保持 4096 / 4096 单一前沿；受制硬门槛违规 0、同层被支配首选 0。
- 本阶段起日期选择原则冻结；不再以降低并列率为目标，也不再增加隐藏权重或总分。下一阶段只做用户文案收束。
- 正式页面、复制分析上下文、时间解析、KeyLine 与关键日期筛选继续保持 legacy 路径不变。

## v13.44.0-alpha.9 · 时间效力模型重构 · 第 9 步

本阶段主题：**剩余并列分型审计**。


- 新增 `scripts/review-liuyao-selection-ties.mjs` 与 `docs/REVIEW_TIES_v13.44.0-alpha.9.md`，专门审计 alpha.8 剩余日期并列，不改变正式 comparator。
- 审计使用六维细粒度 Pareto 作为**诊断基准**：生扶、比和、泄力、耗力分别保留，不再先压成“有助 / 软负担”两枚布尔值；诊断基准不进入生产排序。
- 4096 卦一周选日中，alpha.8 第一前沿与六维诊断完全一致 3234 卦；六维诊断是 alpha.8 严格子集 258 卦；alpha.8 反而是六维诊断严格子集 604 卦。说明 coarse benefit/cost 同时存在“分辨不足”和“过早剪枝”两种问题。
- alpha.8 并列 → 六维诊断单选 255 卦；alpha.8 单选 → 六维诊断并列 528 卦。六维诊断总体并列率为 66.60%，因此不能把“减少并列率”作为正确性的代理指标。
- 六维诊断后的 2728 个剩余并列全部完成分型，未分类 0。主要边界为：纯生扶 vs 纯比和 1862 卦、完全同质日期 618 卦、纯泄力 vs 纯耗力 170 卦；另有“额外助力 vs 额外软负担”等真正多维权衡。
- 审计结论：后续 comparator 若继续重构，应直接基于六维非补偿 Pareto，而不是继续给 coarse benefit/cost 打补丁；但“生扶 vs 比和”“泄力 vs 耗力”仍不得用隐藏权重强行决胜。
- 正式页面、关键节点筛选、时间解析与「复制分析上下文」保持不变。

## v13.44.0-alpha.8 · 时间效力模型重构 · 第 8 步

- 新增 `js/liuyao-time-relevance.js`，把效力事实的结构来源独立映射为相关性层级：直接作用于观察爻 > 观察爻之变 > 世应轴 > 关键关系爻 > 结构组合 > 背景结构。
