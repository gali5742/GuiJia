# 龟甲 v13.42.14

静态八字 / 六爻排盘、结构分析与古籍检索工具。

当前版本已完成 GitHub Pages 首次部署并进入稳定维护阶段。页面本身无需 Vite、Webpack 或服务端运行环境；Node 仅用于测试、vendor 校验和 GitHub Actions 发布。

## 目录

正式仓库建议完整保留：

- `index.html`
- `assets/`
- `data/`
- `js/`
- `vendor/`
- `tests/`
- `scripts/`
- `docs/`
- `.github/`
- `.nojekyll`
- `package.json`
- `vendor-config.json`
- `vendor-versions.json`

生产仓库必须保留已提交并通过 `vendor-lock.json` 校验的 `vendor/` 快照。Pages 构建不再在校验失败时静默联网重建；vendor 缺失或校验失败会直接使 CI / Pages 构建失败。需要更新快照时使用 `Vendor Snapshot PR`。

## 部署前本地检查

无需安装 npm 依赖：

```bash
npm run predeploy
```

该命令会检查：

- 八字 / 六爻核心回归测试；
- 固定依赖版本策略；
- GitHub Actions / Dependabot 必需配置；
- HTML 引用的本地静态资源是否存在；
- 是否出现未经允许的远程可执行脚本。

## GitHub Pages 发布方式

本版本使用 **GitHub Actions**，不要选择旧的 `Deploy from a branch`。

首次上传仓库后：

1. 打开 `Settings → Pages`；
2. 将 Source 设为 **GitHub Actions**；
3. 确认仓库默认分支为 `main`；
4. Actions 中的 `Test and vendor verification` 通过后，再运行/等待 `Deploy GitHub Pages`；
5. 首次正式发布前，建议手动运行一次 `Vendor Snapshot PR`，审核并合并生成的 vendor 快照。

详细步骤见 `docs/DEPLOYMENT_CHECKLIST.md`。

## 《周易》经文

程序优先读取 `data/iching.json`；若不存在，会使用浏览器缓存，再回退到现有远程数据源。

`data/iching.json` 尚未收入一份由本项目核定的完整 64 卦底本，因此这项内容本地化暂缓。它不参与八字四柱、六爻纳甲、世应、用神等核心结构计算。

## JavaScript 结构

- `js/common.js`：日期、时间、真太阳时修正与八字/六爻共用的上下文格式化工具
- `js/iching-loader.js`：《周易》经文的本地 / 缓存 / 远程三级读取
- `js/bazi-core.js`：八字静态规则、五行十神、干支关系与结构计算
- `js/bazi-timing.js`：大运、流年、流月数据组装，节令流月范围与年份定位
- `js/bazi-literature.js`：八字古籍索引与 matcher
- `js/bazi-interpretation.js`：八字原局结构解释与复制分析上下文
- `js/bazi-detail.js`：八字详细分析页的数据整理，展开强弱证据、十神透藏、月令显隐、关系网络与古籍条件对照
- `js/liuyao-core.js`：六爻八宫、纳甲、日月状态、动变、用神与应期核心函数
- `js/liuyao-literature.js`：六爻古籍条目与结构 matcher
- `js/app.js`：Vue 状态、页面导航、选择状态与两套排盘流程编排；不再直接组装岁运领域数据

## Vendor 更新原则

**发现新版不等于升级。**

依赖升级必须同步修改固定版本记录，重新生成 vendor，跑回归测试并人工审核。尤其 lunar-javascript 直接参与历法与四柱计算，不允许自动跟随 `latest`。

详见 `docs/VENDOR_UPDATE_GUIDE.md`。

## v13.42.0 · 六爻主体分析定型

本版将 v13.41.x 的六爻专项开发收束为稳定版本，并保持八字主体逻辑冻结：

- 六爻总览与详细分析职责分离；详细页按“装卦 → 用神分布 → 结构解读 → 应期观察 → 飞伏 / 经文 / 古籍”组织。
- 用神、元神、忌神、仇神统一按明爻、变爻、伏神候选记录，并保留各爻对用神的生克、六合、六冲与动静事实。
- 结构解读固定为最多三层：用神自身状态、用神关系链、动变与卦体结构；复杂卦按语义分点展示。
- 静卦不再生成伪变卦；暗动、日破、回头生克、进退、化空、墓绝长生等动变状态进入统一事实链。
- 动变三合改为按具体爻位与本/变来源识别，区分完整成局与两支待补，避免全局地支拼接造成过度识别。
- 应期观察改为按时间节点聚合；旬空使用“填实 / 冲空 / 出空”，月破使用“逢值 / 合破 / 出破”，同日多项触发合并展示。
- 六爻日辰默认 24:00 换日，并提供 23:00 子初换日选项；所选口径统一作用于日干支、旬空、六神、日辰关系与应期日期。
- “复制分析上下文”已收束为自包含结构事实，包含当前换日口径、同类六亲、飞伏、结构解读、应期与直接相关古籍入口。
- 本轮发布收尾统一页面缓存版本、隐藏无内容的应期卡，并清理过时的开发式说明文字。

## 八字详细分析

- 八字结果页现在分为“原局总览 / 详细分析 / 流年流月”三页；总览继续负责核心结构摘要，详细页负责展开证据。
- 详细页按“日主强弱证据拆解 → 十神透藏分布 → 月令主线与显隐核对 → 干支关系网络 → 古籍条件对照”的顺序组织，并在主要模块先给出一条局部归纳，再展开底层证据。
- 强弱证据把季节、通根、扶助与泄耗克分开陈列；十神分布区分天干明透与地支藏干，不把出现次数换算为力量百分比。
- 干支关系只显示原局实际存在的关系；天干、直接地支关系、完整方局、半合/同方均按实际命中显示，不再用空卡说明“未检测到”。共同节点用于观察多组关系如何集中在同一柱位。
- 古籍条件对照继续复用已核对的原文/条目定位与条件信息，但详细页将“程序、机器、未编码”等实现口吻改写为面向读者的自然说明。
- 页面完全复用现有 `panel-card`、`evidence-list`、`fold-card`、`relation-tag` 等组件，没有增加八字详细页专用 CSS。

## 八字结构解读 v2

- 原局总览“结构解读”由固定分类说明升级为“事实 → 局部命题 → 命题关系 → 核心结构判断”。
- 顶部先给出一条总括判断，再按当前命盘动态生成 3–5 条重点命题；不再机械固定为月令、根气、透干、关系四类。
- 月令判断会同时结合月支本气十神、日主季节状态与根气；透干判断会把同时出现的十神及天干直接关系放在同一命题中；地支多组关系会作为整体网络观察。
- “查看依据”复用全站现有 `fold-card` / `compact-fold` 折叠组件；依据内容改用现有 flex/间距工具类排列，不再套用为“标签—内容”预留固定首列的 `evidence-row`。不新增结构解读专用 CSS。
- 单条判断不再重复显示边界说明，统一收束到模块底部“使用边界”。
- “复制分析上下文”保留详细证据与完整中文干支关系，但用户可见文本只显示“结构解读”，不暴露解释引擎内部版本号；机器关系码仍仅供内部逻辑使用。
- 仍不直接生成吉凶、格局、用神、婚姻、事业或具体事件断语。
